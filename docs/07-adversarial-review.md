# フェーズ6：新しいチャットで敵対的レビュー

## 目的

成果物を作成した会話とは別のチャットを監査担当として使い、実装時の思い込みを引き継がずに検証します。

## なぜ新しいチャットを使うのか

同じ会話で「確認して」と依頼すると、Claudeは自分が先ほど行った処理や説明を前提にしやすくなります。

新しいチャットには次だけを渡します。

- 元CSV 4ファイル
- `reference/requirements.md`
- 作成済みの `integrated_sales.xlsx`
- 作成済みの `management_report.pdf`

Projectを使っている場合、元CSVと要件書はProject knowledgeから参照できます。成果物だけ追加します。

## 監査担当の役割

監査担当は、作成担当の完了報告を信用しません。

元CSVから独立に次を再計算します。

- 入力件数
- 採用件数
- 完全重複件数
- エラー件数
- 支店別の純売上額
- 全体の純売上額

さらに、ExcelとPDFの数値が一致するか確認します。

## 使用プロンプト

`demo-prompts.md` の「8. 敵対的レビュー」を使用します。

## 指摘の分類

### 重大

- 売上や返金の金額が誤っている
- 行が黙って欠落している
- エラー行が正常データへ混ざっている
- ExcelとPDFで主要数値が異なる

### 中程度

- 検証根拠が不足している
- 元行を追跡できない
- 要件の一部が反映されていない

### 軽微

- 表示や文言が分かりにくい
- 並び順、列幅、注記などの改善

実害のない好みは指摘対象にしません。

## 指摘が出た後

監査担当に修正させるのではなく、まず指摘の妥当性を確認します。

1. 指摘された元行を確認する
2. 要件書の該当ルールを確認する
3. 再現方法を確認する
4. 妥当なら作成担当チャットへ戻して修正する
5. 新しい監査チャットまたは同じ監査チャットで再検証する

## 誤検知への対応

AIによるレビューも誤ることがあります。

```text
その指摘を採用する前に、要件書の該当箇所、元CSVの該当行、期待値の計算式を示してください。根拠が不足する場合は指摘を撤回してください。
```

## 良い監査報告

- ファイル名、シート、行、セル等の具体的根拠がある
- 再現手順がある
- 重大度が実害に対応している
- 問題なしの項目も確認結果として残す

## 完了条件

- 元CSVから独立再計算している
- Excel、PDF、Artifactの主要数値を照合している
- 重大な未解決問題がない
- 指摘の根拠が追跡可能
