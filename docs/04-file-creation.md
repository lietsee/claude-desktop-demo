# フェーズ3：ExcelとPDFを作る

## 目的

調査結果と業務要件をもとに、Claude Desktopのコード実行・ファイル作成機能で、実際に使える成果物を作ります。

## 作成物

- `integrated_sales.xlsx`
- `management_report.pdf`

## 実行前の確認

Claudeへ、作業開始前に次を短く再提示させます。

- 採用する変換ルール
- エラーにする条件
- 重複の扱い
- 返金の扱い
- 作成するシートと報告書の構成

この説明が要件書と一致してから、作成を許可します。

## 使用プロンプト

`demo-prompts.md` の「4. Excel・PDF作成」を使用します。

## Excelで見るべき点

### 正規化データ

- 列名と列順が要件通りか
- 日付が統一されているか
- 支店名が3種類へ正規化されているか
- 返金が負数か
- 元ファイルと元行番号が残っているか

### 支店別集計

- 支店順が東京、名古屋、大阪か
- 売上件数と返金件数が分かれているか
- 来店人数と純売上額があるか
- 全体合計との整合が取れているか

### エラー一覧

- 元ファイル、元行、取引ID、理由があるか
- 不正値を黙って直していないか
- 矛盾重複の両方の行が残っているか

### 検証結果

- 入力件数の式が成り立つか
- 支店別合計と全体合計が一致するか
- すべて成功と表示される根拠が書かれているか

## PDFで見るべき点

- 経営者が1〜3分で概要を把握できるか
- 数値がExcelと一致するか
- エラーや注意点を隠していないか
- 日本語が文字化けしていないか
- ページから表や文章がはみ出していないか

## Claudeへ自己検証させる

最初のファイル作成後、`demo-prompts.md` の「5. 成果物の再検証」を入力します。

Claudeに作成済みファイルを再度開かせ、元CSVから独立に計算した値と照合させます。

## なぜ再検証するのか

ファイルを正常に生成できたことと、内容が正しいことは別問題です。

特に確認するのは次です。

```text
入力行数 = 採用行数 + 完全重複除外行数 + エラー行数
```

さらに、Excel、PDF、会話上の完了報告で同じ数値が使われていることを確認します。

## 失敗時の追加指示

### Excelの見た目が悪い

```text
数値や集計ロジックは変更せず、Excelの可読性だけを改善してください。見出し固定、フィルター、列幅、円表記、折り返し、支店別集計の視認性を確認してください。
```

### PDFの日本語が崩れる

```text
日本語表示に対応した方法でPDFを再生成してください。生成後に各ページを画像として確認し、文字化け、欠落、はみ出しがないことを報告してください。
```

## 完了条件

- 2つのファイルをダウンロードできる
- ExcelとPDFの主要数値が一致する
- 検証結果に失敗が残っていない
- 未解決事項が明示されている
